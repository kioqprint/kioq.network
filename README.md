# KIOQ.network

تطبيق Android أصلي باللغة العربية لإدارة تعبئات الهاتف والإنترنت بالجملة لتجار التجزئة في الجزائر.

## القرار المعماري

- تطبيق Android واحد للمالك والتجار، مع واجهات وصلاحيات مختلفة حسب الحساب.
- لا نبني تطبيق ويب للتجار في المرحلة الحالية.
- خادم مركزي وواجهات API آمنة لإدارة الحسابات والأرصدة والديون والتعبئات.
- Kotlin + Jetpack Compose للتطبيق.
- PostgreSQL للخادم المركزي؛ لا تُنفذ تعبئة حقيقية من الهاتف مباشرة.
- تكامل OneClick ومفاتيحه على الخادم فقط.

## بناء APK دون Android Studio

يُبنى التطبيق آلياً عبر GitHub Actions عند كل تحديث إلى فرع `main`، وكذلك عند تشغيل سير العمل يدوياً من تبويب Actions.

- لا يحتاج صاحب المشروع إلى تثبيت Android Studio على حاسوبه.
- بيئة GitHub Actions تستخدم JDK 17 وAndroid SDK 35 وGradle 8.9.
- بعد نجاح البناء، يظهر ملف `app-debug.apk` ضمن Artifacts في تشغيل سير العمل باسم `KIOQ-network-debug-apk`.
- نسخة Debug مخصصة للاختبار وليست إصداراً نهائياً للنشر.

## ما تم بناؤه حتى الآن

- هيكل تطبيق Android أصلي باستخدام Kotlin وJetpack Compose.
- واجهة عربية RTL.
- اختيار Djezzy وOoredoo وMobilis وIDoom Fibre وIDoom 4G.
- اختيار الشحن العادي أو العروض المفعّلة، دون اختراع عروض غير متاحة.
- إدخال الرقم مع بادئة الخدمة، والمبالغ السريعة: 50، 100، 200، 500، 1000، 1500، 2000.
- دفتر جهات اتصال محلي: إضافة وتعديل وحذف وبحث، مع ربط كل جهة بخدمة.
- اقتراح جهات الاتصال المرتبطة بالخدمة أثناء إدخال الرقم.
- أزرار اتصال وWhatsApp لجهات الهاتف، ولا تظهر لخدمات IDoom.
- سجل تعبئة تجريبي مع البحث والتصفية حسب الحالة وعرض التفاصيل.
- إخفاء تكلفة OneClick وهوامش الربح والمراجع الداخلية من واجهة التاجر.

## حدود النسخة الحالية

هذه نسخة تطوير محلية وليست جاهزة للإنتاج:
- جهات الاتصال فقط تحفظ محلياً على الجهاز باستخدام SQLite.
- سجل التعبئة المعروض بيانات توضيحية ثابتة، وليس سجلاً حقيقياً.
- لا توجد مصادقة أو حسابات مالك/تاجر مرتبطة بالخادم حتى الآن.
- لا توجد مزامنة بين الأجهزة.
- لا تتصل النسخة بـ OneClick، ولا تنفذ تعبئات أو تخصم أرصدة.
- واجهة العروض تنتظر بيانات حقيقية من تكامل OneClick.
- أُضيف سير عمل GitHub Actions لبناء APK تلقائياً؛ يجب التأكد من نتيجة أول تشغيل قبل اعتبار البناء ناجحاً.

## قواعد مالية وصلاحيات ثابتة

- حساب المالك هو حساب الجملة الوحيد؛ بقية الحسابات لتجار التجزئة.
- المواطن النهائي لا يملك حساباً في المنصة.
- تكلفة OneClick وهوامش المالك والتفاصيل الداخلية تظهر للمالك فقط.
- التاجر يرى قيمة التعبئة والمبلغ المخصوم من رصيده وحالة عملياته فقط.
- فرض الصلاحيات يجب أن يكون في الخادم وواجهات API، وليس بإخفاء عناصر الواجهة فقط.
- لا تُعاد محاولة طلب مجهول النتيجة تلقائياً قبل الاستعلام عن حالته لدى المزود.

## الخطوات التالية

1. التحقق من نجاح بناء APK عبر GitHub Actions وإصلاح أي أخطاء تظهر.
2. بناء الخادم المركزي والمصادقة والأدوار، مع فصل صلاحيات المالك والتاجر على مستوى API.
3. تصميم دفتر مالي غير قابل لتعديل التاريخ مباشرة، والديون والتحصيل والأرباح.
4. دراسة توثيق OneClick والتحقق من الخدمات والعروض المدعومة فعلياً قبل التكامل.
5. إضافة مزامنة آمنة وتخزين محلي مناسب واختبارات.
