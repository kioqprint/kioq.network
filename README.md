# KIOQ.network

تطبيق Android أصلي باللغة العربية لإدارة تعبئات الهاتف والإنترنت بالجملة لتجار التجزئة في الجزائر.

## القرار المعماري الحالي

- تطبيق Android واحد للمالك والتجار، مع واجهات وصلاحيات مختلفة حسب الحساب.
- لا نبني تطبيق ويب للتجار في المرحلة الحالية.
- خادم مركزي وواجهات API آمنة لإدارة الحسابات والأرصدة والديون والتعبئات.
- Kotlin + Jetpack Compose للتطبيق.
- PostgreSQL للخادم المركزي؛ لا تُنفذ تعبئة حقيقية من الهاتف مباشرة.
- تكامل OneClick ومفاتيحه على الخادم فقط.

## فتح المشروع

افتح المستودع في Android Studio، ثم انتظر مزامنة Gradle وشغّل إعداد التطبيق `app` على محاكي أو جهاز Android.

المتطلبات:
- Android Studio حديث يدعم Android Gradle Plugin 8.7.3.
- JDK 17.
- Android SDK 35.

## الحالة الحالية

بدأ هيكل تطبيق Android وواجهة تعبئة أولية باللغة العربية (RTL):
- اختيار Djezzy وOoredoo وMobilis وIDoom Fibre وIDoom 4G.
- اختيار الشحن العادي أو العروض المفعّلة.
- إدخال رقم ومبلغ واختيار المبالغ السريعة.
- سجل تعبئة توضيحي.

هذه نسخة واجهة محلية فقط: لا تتصل بـ OneClick، ولا تحفظ البيانات، ولا تخصم رصيداً، ولا تنفذ تعبئات حقيقية. بيانات السجل أمثلة فقط.

## قواعد مالية وصلاحيات ثابتة

- حساب المالك هو حساب الجملة الوحيد؛ بقية الحسابات لتجار التجزئة.
- المواطن النهائي لا يملك حساباً في المنصة.
- تكلفة OneClick وهوامش المالك والتفاصيل الداخلية تظهر للمالك فقط.
- التاجر يرى قيمة التعبئة والمبلغ المخصوم من رصيده وحالة عملياته فقط.
- فرض الصلاحيات يجب أن يكون في الخادم وواجهات API، وليس بإخفاء عناصر الواجهة فقط.
- لا تُعاد محاولة طلب مجهول النتيجة تلقائياً قبل الاستعلام عن حالته لدى المزود.

## المراحل التالية

1. استكمال واجهة التعبئة وجهات الاتصال وسجل العمليات.
2. بناء الخادم المركزي والمصادقة والأدوار.
3. تصميم دفتر مالي غير قابل لتعديل التاريخ مباشرة، والديون والتحصيل والأرباح.
4. دراسة توثيق OneClick والتحقق من الخدمات والعروض المدعومة فعلياً قبل التكامل.
5. إضافة التخزين المحلي والمزامنة الآمنة والاختبارات.
